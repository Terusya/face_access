# ML-компоненты системы

## Задачи и подходы

1. **Детекция лица**: RetinaFace или MTCNN — обеспечивают высокую точность даже при частичных окклюзиях.
2. **Оценка качества**: на основе резкости, освещённости, угла поворота. Используем предобученную модель.
3. **Alignment**: выравнивание по ключевым точкам для нормализации.
4. **Liveness (anti-spoofing)**: пассивный метод — анализ микротекстур, отражений, движения (например, DeepFake detection). В PoC — mock, в продакшене — можно использовать готовые модели.
5. **Извлечение эмбеддинга**: ArcFace или FaceNet на ResNet-50. Используем предобученную модель.
6. **Сравнение с базой**: identification (one-to-many) — поиск ближайшего соседа в ANN-индексе (FAISS) по косинусному расстоянию.

**Verification vs Identification:** на проходной нужен identification (кто этот человек), а не verification (подтверждение личности по ID).

**Пороги:**
- `allow_score > 0.7` и отрыв от второго кандидата > 0.1 -> allow.
- `0.5 < allow_score <= 0.7` или малый отрыв -> manual_review.
- `allow_score <= 0.5` -> deny.

**Баланс FAR/FRR:** FAR дороже, поэтому порог сдвинут в сторону меньшего FAR (цена ошибки FAR принимаем как стоимость инцидента безопасности).

**Validation:** валидационный набор собирается по личностям (не по кадрам), включает разные условия освещения, ракурсы, время суток. Метрики: FAR, FRR, EER, latency.

**LLM:** в этой системе не нужен, так как все решения принимаются по чётким правилам и порогам; нет необходимости в генерации текста или сложном рассуждении. или пропуск при выполнении правил, или передача решения охраннику.
