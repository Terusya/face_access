# Риски, надёжность и эксплуатация

## Low-latency, надёжность, деградация
- Достижение 1 секунды: детекция и эмбеддинг на edge (GPU), ANN-поиск (FAISS) на центральном сервере с быстрым сетевым каналом.
- Кеширование базы эмбеддингов на edge (обновление раз в час) для offline-режима.
- При потере сети edge использует локальный кеш (возможна задержка до 1 часа в синхронизации отзывов доступа, что является риском — компенсируется частыми обновлениями).
- Идемпотентность команд: каждый event_id уникален, турникет открывается один раз.
- При недоступности модели/базы — fallback на карточный доступ.

## Privacy, safety, governance
- Биометрические данные: храним только эмбеддинги (необратимое преобразование), исходные изображения не храним.
- Доступ к базе эмбеддингов строго ограничен (ролевая модель, двухфакторная аутентификация).
- Удаление сотрудника: немедленное удаление из центральной БД, асинхронная отправка команды на edge (очередь). Если сотрудник уволен, а edge ещё не обновился — риск, но покрывается тем, что при offline-кеше доступ всё равно будет открыт до обновления (принимаем как допустимый риск на время до 1 часа, но требуем логирования таких событий).
- Защита от model inversion: использование стандартных библиотек, хранение эмбеддингов отдельно от личных данных.
- Аудит всех решений: лог содержит причину решения, но не чувствительные данные (кроме employee_id, который необходим для идентификации).
